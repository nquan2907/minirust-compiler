# Principles Of Programming Languages Course Project Guide (MiniRust)

This project provides the framework for a series of assignments in the Principles Of Programming Languages course. The objective is to step-by-step build a complete compiler for the **MiniRust** programming language (a procedural language combining Rust syntax and C program structure) to compile into Java Virtual Machine bytecode (JVM Bytecode as a set of Jasmin `.j` assembly instructions).

---

## 1. Project Structure

The project directory has the following self-contained structure:
```
minirust-assignment-<MSSV>/
├── venv/                        # Python Virtual Environment
├── requirements.txt             # Required Python libraries list
├── README.md                    # This instruction document
├── specification/               # Folder containing assignment descriptions and PDF specs
├── src/
│   ├── grammar/
│   │   ├── MiniRust.g4          # ANTLR4 Grammar (Lexer & Parser)
│   │   └── (generated files)    # Files generated by ANTLR (after running gen)
│   ├── astgen/                  
│   │   └── ASTGenerator.py      # AST Generation implementation (Assignment 2)
│   ├── checker/                 
│   │   ├── StaticChecker.py     # Semantic Analysis & Type Checker implementation (Assignment 3)
│   │   └── StaticError.py       # Type checker error definitions
│   ├── codegen/                 
│   │   ├── CodeGen.py           # JVM Jasmin Code Generator entry point (Assignment 4)
│   │   ├── Emitter.py           # Jasmin assembly emission utility
│   │   ├── Frame.py             # JVM execution frame helper
│   │   └── (other utilities)    # Code generator helper classes (JasminCode.py, Utils.py, etc.)
│   ├── runtime/                 # Precompiled Jasmin jar, runtime Java class library
│   │   ├── jasmin.jar           # Jasmin assembler (converts .j to .class)
│   │   ├── io.java              # Java standard I/O library for MiniRust programs
│   │   └── io.class             # Compiled io.class library
│   ├── utils/                   
│   │   ├── AST.py               # Abstract Syntax Tree node class definitions
│   │   ├── Visitor.py           # Base AST Visitor pattern implementation
│   │   └── lexerror.py          # Lexical error helper functions
│   └── run.py                   # Dispatcher script for generation and testing
└── test/
    ├── TestUtils.py             # Base class helper for testing comparisons
    ├── test-lexer.py            # Unit tests for Lexical Analysis (Lexer) (Assignment 1)
    ├── test-parser.py           # Unit tests for Syntax Analysis (Parser) (Assignment 1)
    ├── test-ast.py              # Unit tests for AST Generation (Assignment 2)
    ├── test-checker.py          # Unit tests for Semantic Analysis (Assignment 3)
    └── test-codegen.py          # Unit tests for JVM Code Generation (Assignment 4)
```

## 2. Environment Setup Instructions

### Step 0: Clone your private assignment repository
You should have received an email invitation to a private GitHub repository for this assignment. Accept the invitation, then clone the repository to your local machine:
```bash
# Replace <YOUR-USERNAME> and <MSSV> with your GitHub username and student ID.
git clone https://github.com/PPL-CO3005-2025-3/minirust-assignment-<MSSV>.git
```
This will create a folder named `minirust-assignment-<MSSV>` which contains the project files.

**Prerequisite**: You need **Git** installed and accessible via your command line. On macOS and Linux Git is usually pre‑installed; on Windows install *Git for Windows* from https://git-scm.com/download/win.

**How to run the command**: Open a terminal (macOS/Linux) or Command Prompt / PowerShell (Windows) and execute the `git clone …` command there.


To run this project, you need the **Java Runtime Environment (JRE) or JDK** (version 11 or higher) to run the ANTLR4 generator tool and Jasmin assembler, along with **Python (version 3.8 or higher)**.

### Step 1: Install Java
- **Windows**: Download and install Oracle JDK or Adoptium Eclipse Temurin. Ensure that the Java `bin` directory path is added to the system `PATH` environment variable.
- **macOS** (using Homebrew): `brew install openjdk`
- **Linux** (Debian/Ubuntu): `sudo apt update && sudo apt install default-jdk`

### Step 2: Set up Python Virtual Environment (`venv`)


The virtual environment isolates project dependencies to avoid conflicts with your system environment. Open your terminal, change directory into your cloned project root directory `minirust-assignment-<MSSV>/`, and run the following commands:

#### On macOS and Linux:
1. Create the virtual environment:
```bash
python3 -m venv venv
```
2. Activate the virtual environment:
```bash
source venv/bin/activate
```
3. Install required dependencies:
```bash
pip install --upgrade pip
pip install -r requirements.txt
```

#### On Windows (Command Prompt or PowerShell):
1. Create the virtual environment:
```cmd
python -m venv venv
```
2. Activate the virtual environment:
   - In **Command Prompt**:
```cmd
venv\Scripts\activate.bat
```
   - In **PowerShell**:
```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope Process
.\venv\Scripts\Activate.ps1
```
3. Install required dependencies:
```cmd
pip install --upgrade pip
pip install -r requirements.txt
```

### 5.3. Troubleshooting Push Issues

#### Issue A: Push Rejected (Remote contains work you do not have locally)
If you see the following error when running `git push`:
```text
 ! [rejected]        main -> main (fetch first)
error: failed to push some refs...
hint: Updates were rejected because the remote contains work that you do
hint: not have locally.
```
**Why it happens**: The instructor has pushed updates (e.g., bug fixes) to your remote repository on GitHub, making your local clone out-of-date.

**How to resolve**:
1. Run a merge pull to integrate remote changes:
   ```bash
   git pull origin main --no-rebase
   ```
2. If Git opens a text editor to write a merge commit message:
   - **Vim** (shows `~` lines at bottom): Press `Esc`, type `:wq`, and press `Enter`.
   - **Nano** (shows shortcuts at bottom): Press `Ctrl + O`, press `Enter`, then press `Ctrl + X`.
3. Push again:
   ```bash
   git push origin main
   ```

#### Issue B: Accidental modification of read-only/disallowed files (e.g., `src/utils/AST.py`)
If you accidentally modify a file that must not be changed (such as `src/utils/AST.py` or any file outside the allowed submission list), your local execution might succeed, but the remote autograder will silently ignore these modifications. It will use the original clean system files from the template repository to compile and run your code, which may result in a compilation/test failure or a score of **0** on GitHub.

**How to resolve**:
1. **If you have NOT committed the changes yet**:
   You can easily discard your local changes using `git restore` (or `git checkout`):
   ```bash
   git restore src/utils/AST.py
   ```
2. **If you have committed the changes locally but have NOT pushed to GitHub yet**:
   You can restore the clean file directly from your remote repository on GitHub (which still contains the original version):
   ```bash
   git fetch origin
   git checkout origin/main -- src/utils/AST.py
   ```
3. **If you have already pushed the modified file to your remote GitHub repository**:
   You can restore the file from the initial clean commit of your own repository:
   - Find the initial commit hash of your repository (the commit where the template was first created):
     ```bash
     git log --oneline | tail -n 1
     ```
     *(This will output something like `533c86d Initial commit` or similar)*
   - Restore the file from that clean commit:
     ```bash
     git checkout <initial-commit-hash> -- src/utils/AST.py
     ```
   After restoring the file, stage, commit, and push the clean file:
   ```bash
   git add src/utils/AST.py
   ```
   ```bash
   git commit -m "Restore original AST.py"
   ```
   ```bash
   git push origin main
   ```
### 5.4. Grading Results, Explicit Submission, and Push Policy

1. **How to Trigger the Autograder (`[submit]` keyword)**: 
   To prevent consuming your grading quota on broken or incomplete code, the remote autograder **will NOT run automatically** on every standard `git push`. 
   * **To push draft code without grading:** Simply commit and push your code with any normal message. You are encouraged to commit frequently to back up your progress.
   * **To officially trigger the autograder for a test run:** You **MUST** append the exact keyword **`[submit]`** (including square brackets) anywhere inside your commit message. 
   
   *Example of a valid grading trigger:*
   ```bash
   git commit -m "Implement basic arithmetic parser rules [submit]"
   git push origin main
2. **Grading Quota & Limits:**
   - The maximum number of test runs allowed for each assignment is dynamically configured and read from the max_submissions configuration field inside the global deadlines.json below.
   - Any push containing the [submit] keyword after this quota is reached will be rejected by the grading queue and flagged as Exceeded submission limit.
   - Pushes without the [submit] keyword never count against your quota and are unlimited.
3. **Final Score Policy:**
   The explicit test runs requested via [submit] during the semester are purely for your feedback and self-assessment.
   **CRITICAL:** The definitive version used to calculate your final grade for the assignment will be the absolute last push available on your main branch before the official deadline timestamp, regardless of whether that final commit contains the [submit] keyword or not.
4. **View Grading Results:**
   The grading process takes a few minutes to complete after your commit is pushed, so please wait until the commit status check (a small green checkmark or red cross next to the commit SHA on GitHub) appears. You can then click on the icon and select **Details** to view your detailed score report.
